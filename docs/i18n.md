# Internationalization

The application UI and in-app guides support `en` and `zh-CN` from v0.2.0. Launcher/CLI messages and unrecognized third-party errors may retain their original language.

## Catalogs and rendering

Edit `locales/en.json` and `locales/zh-CN.json`. Keys are shared semantic message IDs. Templates use named placeholders (`{p0}`, `{p1}`, etc.); placeholder sets must match in both languages. `locales/server-keys.json` identifies known backend messages, including legacy task stages and errors.

```bash
python3 scripts/build_locales.py
python3 scripts/build_locales.py --check
```

The generated `web/locales.js` loads before `web/i18n.js` and page scripts. No third-party i18n library or network translation service is used. Missing translations fall back to English, then the key.

Static HTML uses `data-i18n` and attribute-specific `data-i18n-placeholder`, `data-i18n-title` and `data-i18n-aria-label`. Never add these attributes to user content. For mixed labels, mark only the UI text, preserving child controls.

Dynamic UI uses lazy `I18n.msg(key, values)` descriptors and explicit `I18n.text(element, value)` or `I18n.attr(element, value, attribute)` bindings. `I18n.join`, `plus` and `parts` preserve descriptors when composing text; ordinary data remains ordinary strings/numbers. `I18n.option` binds translated option labels without changing their values. A locale change re-renders only registered UI text and attributes; it does not scan or translate arbitrary DOM text.

Prompts, preset names, filenames, IDs, enum values, seeds and workflow contents are data, not messages. Interpolated values are opaque. Do not use translated display strings to identify a job, compare workflow parameters or determine API behavior. Use `String(message)` only at a final display/serialization boundary where a stable string is required.

## Language selection and state

Preference order: saved `orion.locale`, supported browser language, English fallback. All Chinese browser variants initially select Simplified Chinese. The header selector saves the explicit choice and synchronizes other tabs via the storage event.

Language switching does not reload the studio/workbench or call generation/cancellation endpoints. Existing text bindings refresh in place, preserving form values, selection, references, drafts, active task IDs and pending idempotency keys. Guides fetch their localized document in place. User-written or previously saved prompts are not rewritten when the locale changes.

## Backend compatibility

Errors retain their original `error` string and gain `error_key` / `error_params` where a known message matches. Existing clients and historical records continue to work. The browser localizes only known backend UI fields through `I18n.server`; it leaves unknown upstream details intact. Do not translate arbitrary fields in API responses or database records.

## Validation

`tests/test_i18n.py` checks catalog/placeholder parity and error descriptors. `tests/browser_i18n.py` checks both pages, locale persistence, browser detection, active tasks, pending request identity, zero seeds, user text matching translated words, guide switching, dynamic errors and mobile overflow. Existing Chinese regressions explicitly set a Chinese browser locale. CI verifies the generated asset is current.

New components should cover visible text, placeholders, titles and accessibility labels in both languages. Test long English labels and preserve user data exactly. Raw provider diagnostics should stay available rather than being silently paraphrased.
