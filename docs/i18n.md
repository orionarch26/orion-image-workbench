# Internationalization design

Status: design for the next implementation milestone. Current UI is Chinese; public README/install instructions are bilingual.

Locales: `en`, `zh-CN`. Preference order: saved explicit choice, supported browser locale, English fallback. Use semantic keys such as `nav.workbench`, `batch.queueCapacity`, and `errors.referenceMissing`. Translate entire messages with named placeholders, rather than concatenating translated fragments.

Provide translations for HTML text, dynamic UI, accessibility labels, validation, task stages, CLI and in-app guides. Model prompts, user preset names, filenames, IDs, numeric values, API keys/enums and saved workflow contents are data, not translatable UI text.

Backend errors should gain stable codes and parameters while retaining legacy error text for existing clients/records. Show raw upstream exceptions in a technical-details area. Do not guess translations for historical private prompts or silently rewrite records.

Language switching must not submit or cancel jobs, change the draft's prompt/seed, or alter an idempotency key. Test active-job switching, persisted choices, missing translations, placeholder parity, and long English labels at desktop/mobile sizes. This work should preserve the existing lightweight frontend rather than require a framework rewrite.
